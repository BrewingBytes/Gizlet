- **UUID Generator** makes identifiers in every version a browser can honestly produce — 4, 7, 1, 6, 3, 5, and the Nil and Max values — one at a time or a thousand at once, from your browser's cryptographic randomness and never from `Math.random`. A GUID is not a different thing from a UUID, so the braces and capitals are offered as a way of writing the same 128 bits, alongside canonical form, no hyphens, and a URN.
- It also reads one. Paste a UUID in any of those styles and the page says which version and variant it is, when it was made if it carries a time, and — for a version 1 — whether the node in it is a real MAC address or a random one. That last question is the difference between a version 1 that identified somebody's machine and one that did not.
- **A version 1 made here cannot leak a MAC address.** A browser cannot read one, so the node field is random with its multicast bit set, which is what RFC 9562 requires of a node that is not a network address — and it means the value says so to anyone who reads it back.
- **A batch of version 7s comes out in order, not merely near it.** A millisecond is long enough that forty made at once would share every ordered bit and differ only in randomness, so the twelve bits after the timestamp carry the monotonic counter RFC 9562 provides for exactly that case.
- **Versions 2 and 8 are explained rather than faked.** Version 2 substitutes a POSIX user or group id into the timestamp, and a browser has no POSIX identity — generating one would mean inventing the field that gives the identifier its meaning. Version 8 is free-form and says nothing without bytes its caller supplies. The page says so, which is more use to whoever came looking than a convincing fake would be.
- Version 3 needed MD5, which `crypto.subtle.digest` refuses outright and correctly. Rather than add a dependency, it is written out in `src/data` and tested against every vector in RFC 1321 — including the million-character one — in the manner of the CRC-32 and the EXIF reader already there. Versions 3 and 5 reproduce the published known-answer vectors, so they interoperate with other implementations rather than merely agreeing with themselves.
