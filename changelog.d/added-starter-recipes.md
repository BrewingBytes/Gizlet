- **Gizlet Flows opens with three flows somebody has already worked out.** An empty builder asks you to know both which Gizlets exist and what order they go in, and a shelf of cards under it now answers that: make a photograph web-ready, bind photographs into one document, or join documents and clear the fields the joined file inherited. Each card says what the flow takes, what it hands back, and what every setting on it does.
- **A card is an ordinary recipe link, not a special case.** It carries the same fragment the Copy recipe link button writes, read by the same decoder, so a starter recipe is simply a flow this site shared. Copy it, send it, open it in a new tab — it behaves like any other flow you were sent.
- **Opening one loads the settings and then stops.** The blocks fill in and nothing runs: there is no file yet, and the file you eventually choose is read in this browser like every other flow's.
- Two of the three say plainly where a link cannot carry what was asked for. Fitting an image's longest side to 1600 is not something a flow can name — a resize block takes an exact width and height — so the web-ready recipe crops to a centred 16:9 rectangle first, which makes one exact pair the right instruction for a picture of any shape, and the document recipe leaves resizing out rather than stretching every photograph to one size.
- The recipe that clears a joined PDF's fields says what that is not. It clears the document's own title, author and software names; it is not redaction, and text under a shape or a name written into a page is untouched.
