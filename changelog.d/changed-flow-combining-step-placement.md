- A flow can no longer be built with one combining step after another. Merge PDF declares `pdf-file` in and `pdf-file` out, so the payload-kind rule would offer it as the block after Image to PDF — but the payload reaching it there is already the single document that step made, and there is nothing to join a lone document to. `isValidFlowSequence` now refuses that arrangement, and the flow builder works out the next block from the whole chain rather than only from the block before it, so Merge PDF has a real flow contract without appearing as a block that could not work. An image flow therefore still ends at the PDF it makes, and Merge PDF's contract holds for a flow that starts from several PDFs. Nothing in the catalogue turns one payload back into several yet; when a Gizlet does, that rule is where it says so.
