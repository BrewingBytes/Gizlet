- The PDF Viewer block in Gizlet Flows, announced in 0.3.0. Adding it printed one status line and showed the visitor nothing: the flow runner carried the document past it untouched, because viewing a result is what a result panel does rather than a pipeline step — no flow needs an Image Viewer block to see an image. Now that the panel previews a PDF, the block has nothing left to do. The `passesInputThrough` contract that described it is gone with it, and a Gizlet that reads and writes nothing another Gizlet can use says so in `flowlessToolSlugs` rather than claiming a pass-through contract, so the guard that catches a Gizlet which forgot its contract still catches one. The PDF Viewer Gizlet itself is unchanged. A recipe link written by 0.3.0 that names `pdf-viewer` as a step is now ignored whole, which is this format's documented behaviour for a recipe it cannot read; no alias is kept, because the window is one release long and the block never ran.
