- **JSON and CSV Converter** moves flat records between the two formats in either direction, both boxes live as you type. Columns come out in the order the keys first appear, so the same records always write the same file, and a key only some records carry still gets a column with an empty cell under it. Each direction says how many rows and columns it produced, and hands the result over as a copy or a file.
- **The quoting is the part that is easy to get wrong.** A value holding the separator, a double quote or a line break is quoted on the way out and read back as one value on the way in, which is what makes the result open in a spreadsheet as the table you meant rather than as confetti. Reading accepts CRLF, LF and CR endings, a byte order mark, and a quoted value that spans several lines.
- **The column separator is chosen, not sniffed** — comma, semicolon, tab or pipe. A semicolon is what a spreadsheet writes where the comma is already the decimal point, which is most of Europe and the usual reason a file opens in Excel as one tall column; when a table comes out one column wide, the page names the separator it should have been read with.
- **A CSV cell is text until you say otherwise.** The default makes every cell a JSON string, so `00713` stays `00713`. Ask for values instead and a cell that is exactly a JSON number, or `true`, `false` or `null`, becomes one — but only when writing it back gives the same characters, so a twenty-digit identifier and `1e3` still come back as text rather than as different numbers.
- **Nested JSON is refused by name rather than flattened.** Flattening means inventing names for the columns it becomes, and every convention is somebody else's wrong one, so the message names the record and the key instead and leaves the job to you.
- **A row that does not match the header is answered two different ways.** One with fewer fields is filled in with empty text and the line is named, because nothing was lost. One with more is refused and nothing is converted, because there is no column for the extra values and dropping them is how a converter loses a field without anybody noticing.
- Records survive a round trip in both directions, with one exception the page states rather than hides: a spreadsheet has no null, so a null is written as an empty cell and an empty cell reads back as an empty string.
- Your records stay on this device, whichever way they are going. Nothing is sent anywhere, and the downloaded file is written by the browser out of what is already on screen.
