- A Split PDF Gizlet, at `/tools/split-pdf/`: open a PDF and either name the ranges you want — `1-3, 5, 8-10` gives three documents — or ask for every page separately and get one PDF per page. The document is drawn beside the field while the pages are being chosen, so a range can be found rather than guessed at, and each part arrives with its own download alongside a single archive of the whole set. The pages are copied rather than redrawn, so what comes out is the same PDF content it went in as: text stays selectable, fonts stay embedded, and nothing is re-encoded. Splitting is usually the step before sending part of a document on, which is exactly when the file on the device is a contract, a payslip, or a medical letter, so reading the PDF, writing each new document, and packing the archive all happen in this browser. A range that runs backwards, a page past the end, or the same range written twice is refused rather than guessed at, and a password-protected PDF, a file that is a PDF in name only, and a one-page document that has nothing to split into are each explained rather than left as a dead button. Documents of up to 500 pages, the same 500 the PDF Viewer will open, so anything this Gizlet produces can be read in the one next to it. It needed no new dependency: `pdf-lib`, already here for Image to PDF and Merge PDF, copies a page tree out as readily as it copies one in. With it the four-Gizlet PDF group is complete.
- Gizlet Flows can now split a document mid-chain. A flow carries a set of PDFs rather than a single one, so a Split PDF block takes the document apart into its pages and every block after it runs over each piece: images can become a PDF, be split back into pages, and be converted to images again in one pass. A set of documents finishes as one archive, the same way a set of images already did.
