- Changelog entries are now written as one file per change in [changelog.d/](changelog.d/), instead of as a new line under `## [Unreleased]` in `CHANGELOG.md`. Every open pull request was editing the same lines of the same file, so the changelog conflicted on almost every rebase, and resolving it by hand is exactly the kind of merge that quietly drops someone else's entry. A new file cannot conflict with another new file. `pnpm run changelog:collect` assembles them into the release section at release time and deletes them, `## [Unreleased]` becomes a pointer to the directory, and the entries themselves are unchanged: same voice, same bullets, same place in the released changelog.
- `pnpm run changelog:draft -- --write` now writes one fragment per drafted entry into `changelog.d/` rather than appending to `CHANGELOG.md`, and never overwrites a file that already exists, so it can be re-run on a branch whose entries have already been rewritten. `--since origin/main` narrows it to the branch in hand.
